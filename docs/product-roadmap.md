# StyleIQ Product Roadmap

**Status:** Proposed plan; dates and estimates will be refined after discovery.

## Phase 0 — Discovery

- Interview 15–20 online fashion shoppers.
- Run structured competitor walkthroughs.
- Validate pain around fit, appearance, privacy, and trust.
- Select initial garment categories.
- Write PRD and baseline metrics.

**Exit criteria:** Evidence-backed problem statement and MVP scope.

## Phase 1 — UX and avatar foundations

- Design measurement-based onboarding.
- Design photo consent and upload flow.
- Implement profile review and deletion UX.
- Build a clickable prototype.
- Test both avatar paths.

**Exit criteria:** Users can complete either flow in usability sessions and understand the data choices.

## Phase 2 — Static virtual try-on

- Select a licensed model/API.
- Implement input validation.
- Support a small category subset (initially simple tops and dresses).
- Generate static previews.
- Add quality checks, retry, and fallback.

**Exit criteria:** Supported sample cases generate usable, clearly labeled previews at an acceptable cost and latency.

## Phase 3 — Fit Intelligence

- Define garment measurement schema.
- Implement category-specific measurement comparisons.
- Explain recommendations and uncertainty.
- Add test cases for missing and inconsistent data.

**Exit criteria:** Fit guidance is traceable to verified inputs and suppresses unsupported claims.

## Phase 4 — Shopping and analytics

- Add product detail and cart integration.
- Add availability checks.
- Instrument journey events.
- Build funnel and operational dashboard.

**Exit criteria:** Complete test journey from discovery to cart with privacy-safe analytics.

## Phase 5 — Validation and expansion

- Conduct usability testing.
- Design controlled experiments.
- Evaluate conversion and return outcomes only when adequate data exists.
- Improve categories and model quality.
- Investigate controlled video previews.

**Exit criteria:** Evidence supports the next investment.

## Prioritization rules

Prioritize features using:
- Customer pain and reach
- Business impact
- Confidence in evidence
- Technical feasibility
- Data availability
- Cost and latency
- Privacy and trust risks

Do not prioritize video simply because it is visually impressive. Validate whether static try-on solves the customer problem first.
